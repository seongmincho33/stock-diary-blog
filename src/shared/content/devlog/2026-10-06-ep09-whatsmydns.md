> *「전파는 퍼져 나가는 게 아니다. 각자의 기억이 만료되는 것이다」*

🗓️ 2026.10.06 (화) · 개발일지 9화 — AWS 왕국 표류기 ⑤: whatsmydns.net으로 DNS 전파 눈으로 확인하기

8화 끝에 느린 서고를 들여다보겠다고 해놨는데, 공방장이 먼저 문을 열었다.

> "서고는 잠시 두시오. 달빛 상단 차원문 건이 먼저요."
>
> "그 두루마리, 아직 표지석에 안 새겼소?"

5화에서 아크만 길드장이 건넨 두루마리(CNAME)를 표지석 관리자에게 넘겨 새겼다. 10분 뒤 길드장의 장부를 열었다. **Pending validation.** 새로고침. 또 새로고침. 원래 세계에서 호가창 새로고침하던 바로 그 손가락이다.

얼마 전 매매일지에 "급한 놈이 진다"고 써놓고, 나는 또 급했다.

## 등장인물

- **천리경 지도** — 하슈 영감 감정소 벽에 걸린 세계 지도(**whatsmydns.net**). 이름을 대면 20개국이 넘는 망루에서 "보인다/안 보인다"가 한꺼번에 켜진다.
- **망루지기들** — 각 나라의 DNS 리졸버. 한 번 본 표지석은 **정해진 시간(TTL)만큼 기억**하고, 그동안은 다시 보러 가지 않는다.
- **아크만 길드장** — AWS 인증 길드(ACM). 5화의 그 사람. 정찰병을 보내 표지석을 확인한다.
- **셸리** — 검은 창의 셸 정령. 이번 화에선 망루 하나를 콕 집어 묻는 역할(`dig`).

## 봉화처럼 보이지만 봉화가 아니다 — DNS 전파와 TTL

"DNS 전파"라는 말 때문에 다들 오해한다. 표지석 하나를 새기면 봉화처럼 마을에서 마을로 불이 옮겨붙는 줄 안다. 아니다.

실제로는 이렇다.

1. 표지석 관리자가 새기면, 그 길드의 **권한 서버**(authoritative)에는 보통 곧바로 반영된다.
2. 전 세계 망루지기(리졸버)들은 **자기가 예전에 본 걸 기억**하고 있다. 그 기억엔 유효기간(**TTL**)이 붙어 있다.
3. 유효기간이 끝난 망루부터 하나씩 권한 서버에 다시 물어보러 간다. 그래서 새 표지석이 **띄엄띄엄** 보이기 시작한다.

그러니까 전파는 퍼지는 게 아니라, **망루마다 기억이 만료되는 시점이 다를 뿐**이다.

하슈 영감이 지도를 보며 한마디 했다.

> "망루는 눈으로 대답하지 않네. 기억으로 대답하지."

#### 함정 — 새기기 전에 물어보면 '없음'을 기억한다

망루지기는 **"없다"는 사실도 기억한다**(부정 캐시). 표지석을 새기기도 전에 급한 마음에 지도부터 돌려보면, 그 망루들은 "그런 표지석 없음"을 기억해 버린다. 얼마나 오래 기억하는지는 그 영지의 SOA 설정에 달렸다.

그 결과, 새긴 뒤에도 그 망루들만 한참 빨간 ✗를 띄운다. **확인 도구가 확인을 늦추는 셈이다.** 새기고 나서 지도를 돌리자. 급한 놈이 진다는 말은 여기서도 통한다.

## 천리경 지도 보는 법 — whatsmydns.net으로 CNAME 확인

[whatsmydns.net](https://www.whatsmydns.net/)에 들어가면 입력칸 하나와 레코드 종류 선택칸 하나가 있다.

| 칸 | 무엇을 넣나 |
|---|---|
| 도메인 | ACM이 준 **레코드 이름 전체** — `_abc123xyz.dalbit-mall.example` |
| 레코드 종류 | **CNAME** |

> 이 글의 영지 이름 `dalbit-mall.example`은 예시 전용으로 예약된 이름이라 실제로는 존재하지 않는다. 각자의 영지 이름으로 바꿔 읽으시라.

검색하면 세계 지도 위에 망루별 결과가 뜬다.

| 표시 | 뜻 |
|---|---|
| 초록 ✓ + 값 | 그 망루에서 표지석이 보인다 |
| 빨강 ✗ | **아직 안 보이거나**, 그 망루와 통신이 안 됐다 |

여기서 ✓ 개수보다 중요한 게 하나 있다. **✓ 옆에 뜬 값을 읽어야 한다.**

```
_qwerty.acm-validations.aws.
```

이렇게 ACM이 준 값이 정확히 나와야 끝이다. ✓가 떴는데 값이 이상하면, 전파가 아니라 **새김이 틀린 것**이다.

## 새김이 틀렸는지 먼저 의심할 것 — 레코드 이름·값 함정 (가비아·후이즈·Route 53)

30분이 지나도 지도가 온통 빨갛다면, 기다림이 아니라 새김을 의심해야 한다. 길드마다 칸을 받는 방식이 다르기 때문이다.

#### 이름 칸 — 도메인이 두 번 붙는 사고

ACM은 레코드 이름을 `_abc123xyz.dalbit-mall.example.`처럼 **영지 이름까지 붙여서** 준다. 그런데 가비아·후이즈 같은 길드는 호스트 칸에 넣은 글자 뒤에 **영지 이름을 알아서 붙인다.** 그래서 전체를 붙여넣으면 이렇게 된다.

```
_abc123xyz.dalbit-mall.example.dalbit-mall.example.
```

AWS 문서에 이 예시가 그대로 실려 있을 만큼 흔한 사고다. 호스트 칸엔 **앞부분 `_abc123xyz`만** 넣는다. 이렇게 잘못 새기면 지도에서 원래 이름은 영원히 ✗다.

#### 값 칸 — 끝의 마침표

값 끝의 마침표(`.`)도 길드마다 다르다. AWS 문서에는 "어떤 업체는 끝 마침표를 기본으로 붙이기 때문에, 직접 붙이면 오류가 난다"고 되어 있다. 그런데 블로그 후기 중엔 반대로 마침표를 붙여야 통했다는 경우도 있다.

그래서 정답을 외우지 말고 **확인**하자. 한쪽 방식으로 새긴 뒤 지도에서 값이 `….acm-validations.aws.`로 깔끔하게 나오는지 보면 된다. 이상하면 다른 방식으로 고친다.

#### Route 53 — 버튼 하나

영지 표지석을 같은 계정의 **Route 53**이 관리한다면 고생할 필요가 없다. 인증서 상세 화면의 Domains 칸에 **「Create records in Route 53」** 버튼이 있다. 누르고 **「Create records」** 를 누르면 길드장이 직접 새겨준다.

버튼이 회색이면 조건을 확인하자. Route 53이 실제 표지석 길드여야 하고, 그 호스팅 영역에 쓰기 권한이 있어야 하고, 아직 검증 전이어야 한다.

#### 6화의 교훈 다시

등기소와 표지석 길드가 다르면, **등기소에 새겨봐야 아무도 못 본다.** 지도가 끝까지 빨갛다면 6화의 주문으로 표지석 길드부터 확인하자.

```bash
dig dalbit-mall.example NS +short
```

## 망루 하나만 콕 집어 묻기 — dig로 리졸버·권한 네임서버 확인

지도는 한눈에 보기 좋고, 셸리는 정확하다.

```bash
# 내 동네 망루
dig _abc123xyz.dalbit-mall.example CNAME +short

# 특정 망루를 콕 집어서
dig @8.8.8.8 _abc123xyz.dalbit-mall.example CNAME +short   # 구글
dig @1.1.1.1 _abc123xyz.dalbit-mall.example CNAME +short   # 클라우드플레어
```

그리고 **최종 판정은 표지석 길드에 직접 묻는 것**이다.

```bash
dig dalbit-mall.example NS +short                                  # 표지석 길드 확인 (6화)
dig @<위에서-나온-네임서버> _abc123xyz.dalbit-mall.example CNAME +short
```

여기서 `_qwerty.acm-validations.aws.`가 나오면 **새김은 끝난 것**이다. 나머지 망루가 빨간 건 기억이 만료되길 기다리는 시간일 뿐이다. 반대로 여기서도 안 나오면 기다려봐야 소용없다. 새김부터 다시 보자.

| 어디서 안 보이나 | 진단 |
|---|---|
| 권한 서버에서도 안 보임 | **새김이 틀렸다** → 이름·값·길드 확인 |
| 권한 서버엔 보이고 일부 망루만 ✗ | **기다리면 된다** → TTL 만료 대기 |
| 권한 서버엔 보이는데 값이 다름 | 값 칸 입력 실수 |

## 길드장의 장부 — ACM Pending validation · 30분 · 72시간

표지석이 보이기 시작했다면 아크만 길드장 차례다. AWS 문서 기준으로 정리하면 이렇다.

| 상황 | 길드장의 장부 |
|---|---|
| 표지석이 보이기 시작 | 최대 **30분** 정도 `Pending validation` 이 더 이어질 수 있다 |
| 정찰 성공 | `ISSUED` — 신원 증명 마법진 발급 |
| **72시간** 동안 못 찾음 | `VALIDATION_TIMED_OUT` — **새로 요청해야 한다** |

길드장은 72시간 동안 정찰병을 계속 보낸다. 그 안에 표지석만 제대로 보이면 된다. 셸리로 장부를 직접 확인할 수도 있다.

```bash
aws acm describe-certificate \
  --certificate-arn <인증서-ARN> \
  --region us-east-1 \
  --query 'Certificate.Status'
```

#### 발급된 뒤에도 표지석은 지우지 말 것

5화에서 말한 그대로다. AWS 문서에 따르면 길드장은 인증서가 쓰이는 동안 **이 CNAME이 남아 있으면 자동으로 갱신**한다. 지우면 갱신도 멈춘다.

덤으로 하나 더. 이 검증 표지석은 **모든 리전에서 통한다.** 5화의 함정대로 인증서를 다른 리전에 만들었다가 us-east-1에서 다시 요청해도, 같은 표지석이 그대로 통과한다. 새로 새길 필요가 없다.

## 자주 밟는 함정 — DNS 전파 확인 체크리스트

| 증상 | 진짜 원인 |
|---|---|
| 새긴 직후 지도가 전부 ✗ | 정상. 망루 기억이 아직 안 만료됨 |
| 새기기 전에 조회했던 망루만 오래 ✗ | 부정 캐시 — "없음"을 기억 중 |
| 30분 넘게 권한 서버에서도 안 보임 | 이름 칸에 영지 이름 중복, 또는 엉뚱한 길드에 새김 |
| ✓는 뜨는데 길드장이 계속 Pending | 값이 다름 — 끝 마침표·오타 확인 |
| Route 53 버튼이 회색 | 다른 계정, 권한 없음, 또는 이미 검증됨 |
| 72시간 지남 | `VALIDATION_TIMED_OUT` → 인증서 새로 요청 |

### 오늘의 교훈

원래 세계에서 나는 호가창을 새로고침하면 가격이 빨리 움직일 줄 알았다. 이세계에서도 길드장 장부를 새로고침하면 인증서가 빨리 나올 줄 알았다. 둘 다 아니었다.

대신 배운 게 있다. **기다리는 것과 손 놓는 것은 다르다.** 권한 서버에 직접 물어서 "새김은 끝났다"를 확인한 뒤에 기다리면, 그건 불안이 아니라 대응이다. 예측하지 말고 대응하라던 그 원칙이, 표지석 앞에서도 똑같이 통했다.

30분이 채 안 돼 장부가 `ISSUED`로 바뀌었다. 마법진은 손에 들어왔으니 이제 차원문에 봉인할 차례다. 그런데 공방장이 미뤄둔 일을 기억하고 있었다. 다음 화는 8화에서 미뤄둔 **느린 서고 — 인덱스와 explain**이다.
