마이크로서비스 모니터링

Microservices monitoring with Prometheus and Grafana

책 부록에 해당하는 별도 폴더입니다. 각 서비스가 Actuator로 Micrometer 메트릭을 노출하면 Prometheus가 5초마다 긁어 가고, Grafana 대시보드로 JVM 메모리·HTTP 요청 수·응답 시간 등을 봅니다. 12장 구성에서 Kafka/Redis/ELK를 빼고 모니터링 스택을 넣은 형태입니다.

  • Micrometer
  • micrometer-registry-prometheus
  • Prometheus
  • Grafana
  • /actuator/prometheus

이 장의 목표

  • Actuator /actuator/metrics와 Prometheus 포맷 엔드포인트 /actuator/prometheus 노출
  • Prometheus scrape 설정, 서비스별 job
  • Grafana에 Prometheus 데이터소스 연결, JVM/Spring Boot 대시보드(예: Grafana 공식 4701) 가져오기
  • 메트릭에 공통 태그(appName)를 붙여 서비스 구분

핵심 코드

prometheus.yml

global:
  scrape_interval: 5s
  evaluation_interval: 5s
scrape_configs:
  - job_name: 'licensingservice'
    metrics_path: '/actuator/prometheus'
    static_configs: [ { targets: ['licensingservice:8080'] } ]
  - job_name: 'organizationservice'
    metrics_path: '/actuator/prometheus'
    static_configs: [ { targets: ['organizationservice:8081'] } ]

MetricsRegistryConfig — 공통 태그

@Configuration
public class MetricsRegistryConfig {
    @Value("${spring.application.name}") String appName;

    @Bean
    MeterRegistryCustomizer<PrometheusMeterRegistry> configureMetricsRegistry() {
        return registry -> registry.config().commonTags("appName", appName);
    }
}

Actuator 노출 (config/licensing-service.properties)

management.endpoints.web.exposure.include = *
management.endpoints.jmx.exposure.include = *
management.endpoint.health.show-details = always
security.oauth2.resource.userInfoUri = http://authenticationservice:8082/user   # 12장 인증 유지

cd Monitoring
./build-for-m1.sh
docker-compose -f docker/docker-compose.yml up

메모

  • 12장처럼 authentication-service 기반 OAuth2가 켜져 있어 /actuator/prometheus도 인증 대상이 될 수 있습니다. Prometheus가 scrape에 실패(401)하면 리소스 서버 설정에서 /actuator/**를 permitAll()로 열어 주세요.
  • gateway·eureka·config·auth 서비스는 scrape 대상에 없습니다. 같은 패턴으로 job을 추가하면 됩니다.
