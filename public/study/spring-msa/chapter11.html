스프링 클라우드 슬루스와 집킨을 이용한 분산 추적

Distributed tracing with Spring Cloud Sleuth and Zipkin

요청 하나가 게이트웨이 → 라이선싱 → 조직 서비스를 거칠 때, 흩어진 로그를 하나의 Trace ID로 묶어 보는 장입니다. Sleuth가 로그에 trace/span ID를 자동으로 찍고, 로그는 Logstash → Elasticsearch → Kibana로 모으며, 호출 구간별 소요 시간은 Zipkin에서 시각화합니다.

  • Spring Cloud Sleuth
  • Zipkin
  • Brave Tracer
  • logstash-logback-encoder
  • Elasticsearch 7.11 / Logstash 7.12 / Kibana 7.13

이 장의 목표

  • Sleuth로 상관관계 ID(trace id) 자동 생성·전파 — 8장에서 손으로 만든 것을 프레임워크가 대신
  • 로그를 JSON으로 직렬화해 Logstash로 전송(TCP 5000), Kibana에서 trace id로 검색
  • Zipkin 서버로 span 전송, 샘플링 비율 조정, 커스텀 span
  • 게이트웨이 응답 헤더에 Sleuth trace id 싣기

핵심 코드

의존성만 넣으면 로그 포맷이 바뀐다

<dependency><groupId>org.springframework.cloud</groupId><artifactId>spring-cloud-starter-sleuth</artifactId></dependency>
<dependency><groupId>org.springframework.cloud</groupId><artifactId>spring-cloud-sleuth-zipkin</artifactId></dependency>
<dependency><groupId>net.logstash.logback</groupId><artifactId>logstash-logback-encoder</artifactId></dependency>

# 로그 한 줄:  INFO [licensing-service,3ff985c3d2dc8a0f,3ff985c3d2dc8a0f,true] …
#                        └ app name      └ trace id         └ span id       └ Zipkin 전송 여부

logback-spring.xml — Logstash로 JSON 전송

<configuration>
  <include resource="org/springframework/boot/logging/logback/base.xml"/>
  <springProperty scope="context" name="application_name" source="spring.application.name"/>
  <appender name="logstash" class="net.logstash.logback.appender.LogstashTcpSocketAppender">
    <destination>logstash:5000</destination>
    <encoder class="net.logstash.logback.encoder.LogstashEncoder"/>
  </appender>
  <root level="INFO">
    <appender-ref ref="logstash"/>
    <appender-ref ref="CONSOLE"/>
  </root>
  <logger name="com.optimagrowth" level="DEBUG"/>
</configuration>

logstash.conf

input  { tcp { port => 5000  codec => json_lines } }
filter { mutate { add_tag => [ "manningPublications" ] } }
output { elasticsearch { hosts => "elasticsearch:9200" } }

Zipkin 설정 (config/licensing-service.properties 등)

spring.zipkin.baseUrl: http://zipkin:9411
spring.sleuth.sampler.percentage: 1        # 100% 샘플링 (운영에선 낮추기)

게이트웨이 — 상관관계 ID를 Sleuth trace id로

@Autowired Tracer tracer;                                   // brave.Tracer

@Bean public GlobalFilter postGlobalFilter() {
    return (exchange, chain) -> chain.filter(exchange).then(Mono.fromRunnable(() -> {
        String traceId = tracer.currentSpan().context().traceIdString();
        exchange.getResponse().getHeaders().add(FilterUtils.CORRELATION_ID, traceId);
    }));
}

8장에서 UUID를 직접 만들던 부분이 Sleuth trace id로 교체되었습니다. 클라이언트는 응답 헤더 tmx-correlation-id로 받은 값을 Kibana/Zipkin에서 그대로 검색하면 됩니다.

메모

  • licensing-service의 service/OrganizationService.java가 이 장에서 삭제되었습니다(6장 이후 사용되지 않던 파일).
  • licensing-service/src/main/resources/.xml이라는 이름 없는 파일이 있습니다 — JSON 콘솔 appender 설정 예시이며 Spring이 읽지 않는 잔재입니다.
  • Kibana 환경변수가 ELASTICSEARCH_URL=http://elasticsearch:9300으로 돼 있는데 9300은 transport 포트입니다. Kibana 7.x는 ELASTICSEARCH_HOSTS를 쓰고 기본값 http://elasticsearch:9200으로 접속하므로 보통은 그냥 동작하지만, 연결 문제가 생기면 9200으로 바꿔보세요.
  • Spring Cloud Sleuth는 2022년 이후 Micrometer Tracing으로 대체되었습니다. 개념(trace/span/baggage)은 동일.
