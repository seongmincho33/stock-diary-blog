스프링 클라우드 게이트웨이를 이용한 서비스 라우팅

Service routing with Spring Cloud Gateway

모든 요청이 거쳐 가는 단일 진입점(API 게이트웨이)을 세웁니다. 라우팅 규칙은 구성 서버에서 내려받고, 전역 필터로 요청마다 상관관계 ID(tmx-correlation-id)를 만들어 심은 뒤 하위 서비스까지 전파합니다. 7장의 UserContext가 여기서 완성됩니다.

  • Spring Cloud Gateway
  • WebFlux / Reactor
  • GlobalFilter
  • DiscoveryLocator
  • RewritePath

이 장의 목표

  • 게이트웨이의 역할 — 정적 라우팅, 동적 라우팅, 인증/인가, 메트릭·로깅 같은 횡단 관심사 집중
  • Eureka와 연동한 자동 라우팅(/organization-service/**)과 수동 라우팅(/organization/** → lb://organization-service)
  • Pre 필터(TrackingFilter): 상관관계 ID 생성 · Post 필터(ResponseFilter): 응답 헤더에 다시 싣기
  • 하위 서비스가 받은 헤더를 다음 호출에도 이어 붙이는 UserContextInterceptor

핵심 코드

라우팅 규칙 (config/gateway-server.yml)

server.port: 8072
spring.cloud.gateway:
  discovery.locator:
    enabled: true                 # Eureka 서비스 ID로 자동 라우팅: /organization-service/**
    lowerCaseServiceId: true
  routes:
  - id: organization-service
    uri: lb://organization-service
    predicates: [ Path=/organization/** ]
    filters:   [ "RewritePath=/organization/(?<path>.*), /$\{path}" ]   # /organization/v1/… → /v1/…
  - id: licensing-service
    uri: lb://licensing-service
    predicates: [ Path=/license/** ]
    filters:   [ "RewritePath=/license/(?<path>.*), /$\{path}" ]

TrackingFilter — pre 필터

@Order(1) @Component
public class TrackingFilter implements GlobalFilter {
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        HttpHeaders h = exchange.getRequest().getHeaders();
        if (isCorrelationIdPresent(h)) {
            logger.debug("tmx-correlation-id found in tracking filter: {}. ", filterUtils.getCorrelationId(h));
        } else {
            String id = UUID.randomUUID().toString();
            exchange = filterUtils.setCorrelationId(exchange, id);    // 요청 헤더에 추가 (immutable → mutate)
            logger.debug("tmx-correlation-id generated in tracking filter: {}.", id);
        }
        return chain.filter(exchange);
    }
}

ResponseFilter — post 필터

@Bean
public GlobalFilter postGlobalFilter() {
    return (exchange, chain) -> chain.filter(exchange).then(Mono.fromRunnable(() -> {
        String correlationId = filterUtils.getCorrelationId(exchange.getRequest().getHeaders());
        exchange.getResponse().getHeaders().add(FilterUtils.CORRELATION_ID, correlationId);
    }));
}

하위 서비스 쪽 — 전파

// UserContextInterceptor: RestTemplate 이 나가는 요청에 헤더를 다시 붙임
headers.add(UserContext.CORRELATION_ID, UserContextHolder.getContext().getCorrelationId());
headers.add(UserContext.AUTH_TOKEN,     UserContextHolder.getContext().getAuthToken());

// LicenseServiceApplication: @LoadBalanced RestTemplate 에 인터셉터 등록
template.setInterceptors(Collections.singletonList(new UserContextInterceptor()));

흐름: 게이트웨이(TrackingFilter) → licensing-service(UserContextFilter가 ThreadLocal에 저장) → RestTemplate(UserContextInterceptor가 헤더 재삽입) → organization-service(UserContextFilter). 로그에 같은 ID가 찍히는지 확인하는 것이 이 장의 핵심 실습입니다.

실행 및 확인

cd chapter8
./build-for-m1.sh
docker-compose -f docker/docker-compose.yml up

# 게이트웨이가 아는 라우트
curl http://localhost:8072/actuator/gateway/routes

# 자동 라우팅 (Eureka 서비스 ID)
curl http://localhost:8072/organization-service/v1/organization/e6a625cc-718b-48c2-ac76-1dfdff9a531e

# 수동 라우팅 (RewritePath)
curl -i http://localhost:8072/organization/v1/organization/e6a625cc-718b-48c2-ac76-1dfdff9a531e
#   응답 헤더에 tmx-correlation-id: <uuid>

curl http://localhost:8072/license/v1/organization/e6a625cc-718b-48c2-ac76-1dfdff9a531e/license/

# 게이트웨이 구성 확인
curl http://localhost:8071/gateway-server/default

메모

  • Spring Cloud Gateway는 WebFlux(Netty) 기반이라 서블릿 Filter가 아닌 GlobalFilter/ServerWebExchange를 씁니다. 요청 객체가 불변이라 exchange.mutate()로 새로 만듭니다.
  • 9장부터 Postman 요청이 전부 localhost:8072(게이트웨이)를 통해 들어갑니다.
  • Zuul(1판)은 유지보수 모드라 2판에서 Spring Cloud Gateway로 교체되었습니다.
