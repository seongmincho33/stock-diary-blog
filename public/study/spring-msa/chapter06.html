서비스 디스커버리

On service discovery

두 번째 서비스 organization-service가 등장하고, 라이선싱 서비스가 조직 서비스를 호출해야 하는 상황이 생깁니다. IP를 하드코딩하는 대신 Eureka에 서비스가 스스로 등록하고, 클라이언트는 이름(organization-service)으로 찾아 호출합니다. Initial(Eureka 없음)과 Final(Eureka 적용) 두 버전이 있습니다.

  • Netflix Eureka
  • Spring Cloud LoadBalancer
  • OpenFeign
  • @LoadBalanced RestTemplate
  • DiscoveryClient

이 장의 목표

  • 서비스 디스커버리가 필요한 이유 — 수평 확장, 인스턴스 IP 변동, 클라이언트 측 로드밸런싱
  • Eureka 서버 띄우기(@EnableEurekaServer)와 서비스 등록(@EnableDiscoveryClient)
  • 세 가지 호출 방식 비교:
    1. DiscoveryClient — 인스턴스 목록을 직접 받아 URL 조립 (저수준, 로드밸런싱 없음)
    2. @LoadBalanced RestTemplate — http://organization-service/… 처럼 서비스 이름으로 호출
    3. Feign — 인터페이스에 애너테이션만 붙이면 구현체 자동 생성

Initial vs Final

InitialFinal
모듈configserver, licensing-service, organization-service+ eurekaserver
licensing-service 의존성config, openfeign, netflix-ribbonconfig, eureka-client, loadbalancer, openfeign (ribbon 제외)
LicenseServiceApplication둘 다 @EnableDiscoveryClient @EnableFeignClients + @LoadBalanced RestTemplate — Initial은 등록할 레지스트리가 없어 호출이 실패하는 "출발점"
configserver/configlicensing/organization 속성+ eureka-server.yml, 각 서비스 속성에 eureka.client.* 추가
docker-composedatabase, configserver, licensing, organization+ eurekaserver(:8070)

책을 따라가며 직접 Eureka를 붙여보려면 Initial에서 시작하고, 결과만 보려면 Final을 실행하세요.

핵심 코드

Eureka 서버 설정 (config/eureka-server.yml)

server.port: 8070
eureka:
  instance.hostname: eurekaserver
  client:
    registerWithEureka: false      # 자기 자신은 등록 안 함
    fetchRegistry: false
    serviceUrl.defaultZone: http://${eureka.instance.hostname}:${server.port}/eureka/
  server.waitTimeInMsWhenSyncEmpty: 5

클라이언트 등록 (config/licensing-service.properties)

eureka.instance.preferIpAddress = true
eureka.client.registerWithEureka = true
eureka.client.fetchRegistry = true
eureka.client.serviceUrl.defaultZone = http://eurekaserver:8070/eureka/

세 가지 클라이언트

// 1) DiscoveryClient — 인스턴스 목록을 받아 직접 URL 생성
List<ServiceInstance> instances = discoveryClient.getInstances("organization-service");
String uri = String.format("%s/v1/organization/%s", instances.get(0).getUri(), organizationId);

// 2) @LoadBalanced RestTemplate — 호스트 자리에 서비스 이름
restTemplate.exchange("http://organization-service/v1/organization/{organizationId}",
                      HttpMethod.GET, null, Organization.class, organizationId);

// 3) Feign — 인터페이스만 선언
@FeignClient("organization-service")
public interface OrganizationFeignClient {
    @RequestMapping(method = GET, value = "/v1/organization/{organizationId}", consumes = "application/json")
    Organization getOrganization(@PathVariable("organizationId") String organizationId);
}

LicenseService.retrieveOrganizationInfo()가 clientType(feign / rest / discovery) 문자열로 셋 중 하나를 고릅니다. 컨트롤러에 GET …/license/{licenseId}/{clientType} 엔드포인트가 추가된 이유입니다.
