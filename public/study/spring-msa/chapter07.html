나쁜 상황에 대비하기: Spring Cloud와 Resilience4j를 사용한 회복성 패턴

When bad things happen: Resiliency patterns with Spring Cloud and Resilience4j

의존하는 서비스가 느려지거나 죽었을 때 내 서비스까지 같이 무너지지 않게 하는 장입니다. LicenseService.getLicensesByOrganization() 한 메서드에 서킷 브레이커·재시도·속도 제한·벌크헤드를 차례로 얹고, 1/3 확률로 5초 지연을 일으키는 코드로 장애를 흉내 냅니다.

  • Resilience4j (spring-boot2)
  • @CircuitBreaker
  • @Retry
  • @RateLimiter
  • @Bulkhead THREADPOOL
  • spring-boot-starter-aop

이 장의 목표

  • 클라이언트 측 회복성 4패턴 — 클라이언트 로드밸런싱, 서킷 브레이커, 폴백, 벌크헤드
  • Hystrix 대신 Resilience4j — 애너테이션 기반, AOP로 동작
  • 서킷 브레이커 상태 전이(CLOSED → OPEN → HALF_OPEN)와 링 버퍼/실패율 임계값 튜닝
  • 재시도(Retry), 속도 제한(RateLimiter) 패턴
  • 스레드 풀 벌크헤드에서 ThreadLocal 컨텍스트가 끊기는 문제와 해결(UserContext)

핵심 코드

보호 대상 메서드

// @CircuitBreaker(name = "licenseService")   // 코드 7-2: 서킷 브레이커만 (포크가 주석으로 병기)
@CircuitBreaker(name = "licenseService",        fallbackMethod = "buildFallbackLicenseList")
@RateLimiter   (name = "licenseService",        fallbackMethod = "buildFallbackLicenseList")
@Retry         (name = "retryLicenseService",   fallbackMethod = "buildFallbackLicenseList")
@Bulkhead      (name = "bulkheadLicenseService", type = Type.THREADPOOL, fallbackMethod = "buildFallbackLicenseList")
public List<License> getLicensesByOrganization(String organizationId) throws TimeoutException {
    logger.debug("getLicensesByOrganization Correlation id: {}",
            UserContextHolder.getContext().getCorrelationId());
    randomlyRunLong();                                   // 1/3 확률로 5초 sleep 후 TimeoutException
    return licenseRepository.findByOrganizationId(organizationId);
}

private List<License> buildFallbackLicenseList(String organizationId, Throwable t) {
    License license = new License();
    license.setLicenseId("0000000-00-00000");
    license.setOrganizationId(organizationId);
    license.setProductName("Sorry no licensing information currently available");
    return List.of(license);                             // 실제 코드는 ArrayList
}

폴백 메서드는 원본과 같은 시그니처 + 마지막에 Throwable이어야 합니다. 애너테이션이 여러 개일 때 Resilience4j의 적용 순서는 기본적으로 Retry → CircuitBreaker → RateLimiter → TimeLimiter → Bulkhead 순(바깥→안쪽)입니다.

bootstrap.yml — 설정값

resilience4j.circuitbreaker.instances:
  licenseService:
    registerHealthIndicator: true
    ringBufferSizeInClosedState: 5        # 닫힘 상태에서 최근 5회 호출로 판단
    ringBufferSizeInHalfOpenState: 3
    waitDurationInOpenState: 10s          # 열림 유지 시간
    failureRateThreshold: 50              # 50% 실패하면 OPEN
    recordExceptions: [HttpServerErrorException, IOException, TimeoutException, ResourceAccessException]
  organizationService: { ringBufferSizeInClosedState: 6, … failureRateThreshold: 60 }

resilience4j.ratelimiter.instances.licenseService:
  limitForPeriod: 5                       # 5초(limitRefreshPeriod)에 5회
  limitRefreshPeriod: 5000
  timeoutDuration: 1000ms

resilience4j.retry.instances.retryLicenseService:
  maxRetryAttempts: 5
  waitDuration: 10000
  retry-exceptions: [java.util.concurrent.TimeoutException]

resilience4j.bulkhead.instances.bulkheadLicenseService:        # 세마포어 벌크헤드
  maxWaitDuration: 2ms
  maxConcurrentCalls: 20
resilience4j.thread-pool-bulkhead.instances.bulkheadLicenseService:   # 스레드 풀 벌크헤드
  maxThreadPoolSize: 1
  coreThreadPoolSize: 1
  queueCapacity: 1

UserContext — 왜 필요한가

스레드 풀 벌크헤드는 메서드를 다른 스레드에서 실행하므로, 요청 스레드의 ThreadLocal(상관관계 ID 등)이 보이지 않습니다. 이 장에서는 UserContextFilter가 HTTP 헤더(tmx-correlation-id 등)를 UserContextHolder(ThreadLocal)에 넣는 부분까지 구현하고, 8장에서 게이트웨이가 헤더를 만들어 주면서 전체 흐름이 완성됩니다.

@Component
public class UserContextFilter implements Filter {
    public void doFilter(ServletRequest req, ServletResponse res, FilterChain chain) {
        HttpServletRequest http = (HttpServletRequest) req;
        UserContextHolder.getContext().setCorrelationId(http.getHeader(UserContext.CORRELATION_ID));
        UserContextHolder.getContext().setUserId(http.getHeader(UserContext.USER_ID));
        UserContextHolder.getContext().setAuthToken(http.getHeader(UserContext.AUTH_TOKEN));
        UserContextHolder.getContext().setOrganizationId(http.getHeader(UserContext.ORGANIZATION_ID));
        chain.doFilter(http, res);
    }
}
