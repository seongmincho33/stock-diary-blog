Welcome to Docker

3장의 licensing-service를 그대로 가져와 Docker 이미지로 포장하는 장입니다. 자바 코드는 거의 안 바뀌고 Dockerfile, docker-compose.yml, Maven 도커 플러그인이 추가됩니다. 이후 모든 장은 이 방식으로 실행됩니다.

  • Docker
  • docker-compose
  • dockerfile-maven-plugin 1.4.13
  • openjdk:11-slim

이 장의 목표

  • 컨테이너 vs VM, Docker 아키텍처(데몬·이미지·컨테이너·레지스트리)
  • Spring Boot JAR를 담는 멀티스테이지 Dockerfile 작성 — 이미지 크기와 레이어 캐시 최적화
  • Maven 빌드 단계에서 이미지까지 만들기(mvn clean package dockerfile:build)
  • docker-compose로 서비스 실행·환경변수 주입

핵심 코드

Dockerfile — 멀티스테이지

# stage 1: JAR를 풀어서 레이어 분리
FROM openjdk:11-slim as build
ARG JAR_FILE
COPY ${JAR_FILE} app.jar
RUN mkdir -p target/dependency && (cd target/dependency; jar -xf /app.jar)

# stage 2: 풀어놓은 것만 복사 → lib(의존성)와 classes(내 코드)가 다른 레이어
FROM openjdk:11-slim
VOLUME /tmp
ARG DEPENDENCY=/target/dependency
COPY --from=build ${DEPENDENCY}/BOOT-INF/lib     /app/lib
COPY --from=build ${DEPENDENCY}/META-INF         /app/META-INF
COPY --from=build ${DEPENDENCY}/BOOT-INF/classes /app
ENTRYPOINT ["java","-cp","app:app/lib/*","com.optimagrowth.license.LicenseServiceApplication"]

의존성 레이어를 따로 두면 코드만 바뀌었을 때 재빌드/재푸시가 훨씬 빨라집니다. java -jar 대신 -cp로 메인 클래스를 직접 지정하는 점에 주의.

pom.xml — 이미지 이름 규칙

<properties>
  <docker.image.prefix>ostock</docker.image.prefix>
</properties>
…
<plugin>
  <groupId>com.spotify</groupId>
  <artifactId>dockerfile-maven-plugin</artifactId>
  <configuration>
    <repository>${docker.image.prefix}/${project.artifactId}</repository>  <!-- ostock/licensing-service -->
    <tag>${project.version}</tag>                                          <!-- 0.0.1-SNAPSHOT -->
    <buildArgs><JAR_FILE>target/${project.build.finalName}.jar</JAR_FILE></buildArgs>
  </configuration>
</plugin>

docker-compose.yml

services:
  licensingservice:
    image: ostock/licensing-service:0.0.1-SNAPSHOT
    ports: ["8080:8080"]
    environment:
      - "SPRING_PROFILES_ACTIVE=dev"

실행

cd chapter4/licensing-service

# Apple Silicon
./build-for-m1.sh
#   = mvn clean package
#     docker build -t ostock/licensing-service:0.0.1-SNAPSHOT --build-arg JAR_FILE=target/licensing-service-0.0.1-SNAPSHOT.jar ./

# Intel (spotify 플러그인)
mvn clean package dockerfile:build

docker-compose up
curl http://localhost:8080/v1/organization/optimaGrowth/license/0235431845

dockerfile-maven-plugin은 2020년 이후 관리되지 않습니다. arm64 맥에서 빌드가 실패하면 build-for-m1.sh를 쓰고, 새로 프로젝트를 만든다면 Spring Boot 2.3+의 spring-boot:build-image(Buildpacks)나 Jib을 고려하세요.

메모

  • application.properties는 Actuator 엔드포인트 목록이 주석으로 정리돼 있고, enabled-by-default=false + health만 켜는 보수적 설정입니다.
  • 5장부터는 멀티 모듈 루트 pom.xml로 여러 서비스를 한 번에 빌드하고, compose 파일이 docker/ 하위로 이동합니다.
