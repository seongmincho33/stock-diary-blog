마이크로서비스 배포

Deploying your microservices

지금까지 만든 6개 서비스를 AWS에 배포하는 장입니다. 이미지를 ECR에 올리고, EKS(Kubernetes) 매니페스트로 띄우며, Jenkins 파이프라인으로 빌드→이미지→배포를 자동화합니다. 구성 서버는 로컬 파일 대신 Git 저장소에서 설정을 읽고, 인증은 Keycloak 대신 자체 authentication-service(Spring Security OAuth2 + JWT)를 씁니다.

  • AWS ECR / EKS / RDS·ElastiCache(책)
  • kubectl · kompose · Helm
  • Jenkins Pipeline
  • Spring Security OAuth2 (JWT)
  • 이미지 태그 :chapter12

이 장의 목표

  • 빌드/배포 파이프라인의 원칙 — 자동화, 불변 서버(이미지), 환경별 설정 외부화
  • AWS 인프라 준비: RDS(PostgreSQL), ElastiCache(Redis), EKS 클러스터, ECR 저장소
  • docker-compose → Kubernetes 매니페스트 변환(kompose), Deployment/Service(NodePort)로 배포
  • Jenkins 서버 구축(EC2)과 Jenkinsfile로 GitHub → Maven → Docker → ECR → EKS 자동화
  • ELK + Zipkin은 별도 EC2에 compose로 운영

핵심 코드

authentication-service — JWT 발급

// JWTOAuth2Config
clients.inMemory()
    .withClient("ostock").secret("{noop}thisissecret")
    .authorizedGrantTypes("refresh_token", "password", "client_credentials")
    .scopes("webclient", "mobileclient");

endpoints.tokenStore(tokenStore)                          // JwtTokenStore
        .accessTokenConverter(jwtAccessTokenConverter)    // signing.key 로 서명
        .tokenEnhancer(tokenEnhancerChain)                // + authentication_name 클레임
        .authenticationManager(authenticationManager)
        .userDetailsService(userDetailsService);

// WebSecurityConfigurer
auth.inMemoryAuthentication()
    .withUser("john.carnell").password("{noop}password2").roles("USER").and()
    .withUser("illary.huaylupo").password("{noop}password1").roles("USER", "ADMIN");

리소스 서버 — organization-service

@Configuration
public class ResourceServerConfiguration extends ResourceServerConfigurerAdapter {
    public void configure(HttpSecurity http) throws Exception {
        http.authorizeRequests()
            .antMatchers(HttpMethod.DELETE, "/v1/organization/**").hasRole("ADMIN")
            .anyRequest().authenticated();
    }
}

Jenkinsfile — 파이프라인 5단계

node {
  stage('Preparation') { git 'https://github.com/klimtever/smia2-configserver-jenkins.git'; mvnHome = tool 'M2_HOME' }
  stage('Build')       { sh "'${mvnHome}/bin/mvn' -Dmaven.test.failure.ignore clean package" }
  stage('Results')     { junit '**/target/surefire-reports/TEST-*.xml'; archiveArtifacts 'configserver/target/*.jar' }
  stage('Build image') { sh "mvn -Ddocker.image.prefix=758417428849.dkr.ecr.ap-northeast-2.amazonaws.com/ostock \
                              -Dproject.artifactId=configserver -Ddocker.image.version=chapter12 dockerfile:build" }
  stage('Push image')  { docker.withRegistry('https://758417428849.dkr.ecr.ap-northeast-2.amazonaws.com', 'ecr:ap-northeast-2:ecr-user') {
                           sh "docker push …/ostock/configserver:chapter12" } }
  stage('Kubernetes deploy') { kubernetesDeploy configs: 'configserver-deployment.yaml', kubeconfigId: 'kubeconfig' }
}

실행 (로컬) 및 배포 순서

# 로컬에서 전체 기동 (Keycloak 없이 authentication-service 사용)
cd chapter12
./build-for-m1.sh                       # 이미지 태그 :chapter12
docker-compose -f docker/docker-compose.yml up

# 토큰 발급 (password grant)
curl -X POST http://localhost:8082/oauth/token -u ostock:thisissecret \
     -d 'grant_type=password&username=illary.huaylupo&password=password1&scope=webclient'
# 토큰으로 호출
curl -H "Authorization: Bearer $TOKEN" http://localhost:8072/organization/v1/organization/e839ee96-28de-4f67-bb79-870ca89743a0
# AWS 배포 (포크 스크립트 기준, 리전 ap-northeast-2)
aws ecr get-login-password --region ap-northeast-2 | docker login --username AWS --password-stdin <ACCOUNT>.dkr.ecr.ap-northeast-2.amazonaws.com
./ecr-create-repo.sh                    # ostock/{configserver,gatewayserver,eurekaserver,authentication-service,licensing-service,organization-service}
./tag-services.sh  <ACCOUNT_ID>         # ostock/x:chapter12 → <ACCOUNT>.dkr.ecr…/ostock/x:chapter12
./push-services.sh <ACCOUNT_ID>

eksctl create cluster --name ostock-dev-cluster --region ap-northeast-2 …   # (책 12.2절)
aws eks update-kubeconfig --name ostock-dev-cluster
kubectl apply -f AWS/EKS/postgres.yaml
kubectl apply -f AWS/EKS/                # deployment + service 전부
kubectl get svc                          # NodePort 확인

이 장은 그대로 실행되지 않는 부분이 많습니다. 매니페스트·Jenkinsfile에 박힌 AWS 계정 ID(758417428849)와 ECR 주소는 포크 작성자의 것이고, 구성 서버가 가리키는 ihuaylupo/config Git 저장소의 내용(RDS/ElastiCache 엔드포인트 등)도 본인 환경으로 바꿔야 합니다. EKS는 시간당 과금되니 실습 후 eksctl delete cluster를 잊지 마세요.

메모

  • FORK 리전 us-east-2 → ap-northeast-2, 태그 :latest → :chapter12, ECR URI에 https 추가, 생성/태그/푸시 스크립트 추가(2022-04).
  • README에 "Java 12"라고 적혀 있지만 pom.xml은 여전히 Java 11입니다(오타).
  • authentication-service는 1판 스타일의 spring-security-oauth2(deprecated) 기반입니다. 9장의 Keycloak과 둘 다 경험해 보는 셈.
  • 로깅은 logback-delayed.xml로 바뀌어 Logstash 주소를 logstash.host 속성(Git 구성)에서 읽습니다 — ELK가 별도 EC2에 있기 때문.
  • AWS/EC2/docker-compose.yml은 Elasticsearch/Kibana/Logstash 7.7.0 + Zipkin만 있는 모니터링 전용 스택입니다.
