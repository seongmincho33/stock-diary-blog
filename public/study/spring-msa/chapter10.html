스프링 클라우드 스트림을 사용한 이벤트 기반 아키텍처

Event-driven architecture with Spring Cloud Stream

조직 정보가 바뀌면 조직 서비스가 Kafka 토픽에 이벤트를 발행하고, 라이선싱 서비스가 그 이벤트를 구독합니다. 라이선싱 서비스는 조직 정보를 Redis에 캐시해 두고 매번 REST 호출하지 않도록 바뀝니다. 동기 호출 의존을 줄이는 "메시지 기반 느슨한 결합"이 주제입니다.

  • Spring Cloud Stream
  • Kafka + ZooKeeper
  • @EnableBinding / Source / @StreamListener
  • Spring Data Redis (Jedis)
  • @RedisHash

이 장의 목표

  • 동기 REST 호출 vs 메시징 — 결합도, 내구성, 확장성, 유연성 관점 비교와 주의점(순서·의미 불명확성)
  • Spring Cloud Stream 개념: Source / Channel / Binder / Sink
  • 발행자(organization-service)와 소비자(licensing-service) 작성, 사용자 정의 채널
  • Redis를 분산 캐시로 사용하고, 변경 이벤트로 캐시를 무효화하는 패턴

발행자 — organization-service

@SpringBootApplication @RefreshScope
@EnableBinding(Source.class)                 // 기본 "output" 채널 바인딩
public class OrganizationServiceApplication { … }

@Component
public class SimpleSourceBean {
    @Autowired public SimpleSourceBean(Source source) { this.source = source; }

    public void publishOrganizationChange(ActionEnum action, String organizationId) {
        OrganizationChangeModel change = new OrganizationChangeModel(
            OrganizationChangeModel.class.getTypeName(), action.toString(),
            organizationId, UserContext.getCorrelationId());        // 8장의 상관관계 ID를 메시지에도
        source.output().send(MessageBuilder.withPayload(change).build());
    }
}

// OrganizationService
public Organization create(Organization org) {
    org = repository.save(org);
    simpleSourceBean.publishOrganizationChange(ActionEnum.CREATED, org.getId());
    return org;
}

public Organization getOrganization(String organizationId) {
    Organization organization = checkRedisCache(organizationId);          // 1. 캐시
    if (organization != null) return organization;

    ResponseEntity<Organization> r = restTemplate.exchange(              // 2. 게이트웨이 경유 REST
        "http://gateway:8072/organization/v1/organization/{organizationId}",
        HttpMethod.GET, null, Organization.class, organizationId);

    organization = r.getBody();
    if (organization != null) cacheOrganizationObject(organization);       // 3. 캐시에 저장
    return organization;
}

메모

  • FORK ActionEnum(GET/CREATED/UPDATED/DELETED)은 책 본문과 맞추려고 추가된 것인데, 소비자 쪽 switch는 여전히 "SAVE"/"UPDATE"/"DELETE" 문자열을 비교합니다. 그래서 GET 외에는 default 분기(UNKNOWN 로그)로 빠집니다. 책처럼 캐시 무효화(redisRepository.deleteById)를 구현하려면 이 불일치부터 고쳐야 합니다 — 좋은 실습 거리.
  • 이 장에서는 9장의 Keycloak/SecurityConfig가 빠져 있습니다. Kafka·Redis 실습에 집중하기 위한 구성이며 11장도 같습니다.
  • wurstmeister/kafka 이미지는 KAFKA_CREATE_TOPICS=dresses:1:1,ratings:1:1처럼 무관한 토픽 예시를 만들지만 orgChangeTopic은 바인더가 자동 생성합니다.
  • Spring Cloud Stream 3.x의 함수형 스타일(Supplier/Consumer 빈)이 아니라 애너테이션 스타일(@EnableBinding)입니다. 최신 버전에서는 deprecated.
