스프링 클라우드 컨피그 서버로 구성 관리

Controlling your configuration with the Spring Cloud Configuration Server

설정을 코드에서 떼어내 중앙 구성 서버에서 내려받도록 바꾸는 장입니다. 이와 함께 처음으로 PostgreSQL + Spring Data JPA가 들어와 라이선스가 실제 DB에 저장되고, DB 비밀번호는 암호화해서 보관합니다. 이 장부터 멀티 모듈 + docker-compose 구조가 됩니다.

  • Spring Cloud Hoxton.SR1
  • spring-cloud-config-server
  • Spring Data JPA
  • PostgreSQL
  • @RefreshScope

이 장의 목표

  • 구성 관리 원칙: 분리 · 추상화 · 중앙 집중 · 견고함
  • Config Server 백엔드 — 클래스패스(native) / Git / Vault
  • 클라이언트가 bootstrap.yml로 서버를 찾고, 프로파일(dev/prod)별 속성을 받는 흐름
  • @ConfigurationProperties로 속성 바인딩, @RefreshScope + POST /actuator/refresh로 재시작 없이 갱신
  • 대칭키(ENCRYPT_KEY)로 민감 정보 암호화 — {cipher}…

  application.name: config-server
  profiles.active: native          # , git, vault 로 바꿔가며 실험

JPA 엔티티

@Entity @Table(name="licenses")
public class License extends RepresentationModel<License> {
    @Id @Column(name = "license_id") private String licenseId;
    private String description;
    @Column(name = "organization_id") private String organizationId;
    @Column(name = "product_name")    private String productName;
    @Column(name = "license_type")    private String licenseType;
    private String comment;
}
public interface LicenseRepository extends CrudRepository<License, String> {
    List<License> findByOrganizationId(String organizationId);
    License findByOrganizationIdAndLicenseId(String organizationId, String licenseId);
}

메모

  • FORK 원본과 달리 encrypt.enabled=false이고 키가 바뀌어 있습니다. 따라서 {cipher} 값은 클라이언트가 ENCRYPT_KEY 환경변수로 복호화합니다 — compose에서 licensingservice에도 같은 키를 넣는 이유.
  • FORK Vault 백엔드 속성이 추가돼 있어 profiles.active: vault로 바꾸면 로컬 Vault(8200)에서 읽을 수 있습니다. Postman "Chapter-5 GET Vault /licensing/dev" 참고.
  • Organization 모델과 OrganizationService가 미리 들어 있지만, 실제 조직 서비스 호출은 6장에서 시작됩니다.
  • 샘플 조직 ID: e6a625cc-…(Ostock), d898a142-…(OptimaGrowth), e839ee96-…(Ostock). 이후 장의 Postman 요청이 모두 이 ID를 씁니다.
